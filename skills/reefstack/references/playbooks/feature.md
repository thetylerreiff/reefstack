# Feature playbook

Use for authorized new or changed observable behavior. Structure-only changes belong to [Refactoring](refactoring.md), measured optimization to [Performance](performance.md), and disposable decision experiments to [Prototype](prototype.md). A routine change uses only relevant steps and targeted checks; an obvious small edit stays direct. Use [Design](../../../design/SKILL.md) when ownership or shared contracts need settling. The steps form a [dependency graph](graph.md).

1. **Define the result.** Capture the user's outcome, constraints, authorization, and affected user paths. Settle any blocking product choice before dependent work; a prototype's `decision` arrives here as a constraint. Routine work skips inapplicable design ceremony. **Output:** `acceptance`: acceptance conditions and the remaining work items. **Check:** before substantial implementation, each acceptance condition names something checkable.
2. **Set contracts and ownership.** Describe caller behavior, shared shapes, dependencies, writable boundaries, and representative cases. Name independent workstreams, shared state, and the smallest safe decomposition; tightly coupled work stays with the parent. For consequential work whose reach is not already known, use [Blast radius](../../../blast-radius/SKILL.md) to find what depends on the changed code and the fact the change is safe because of. **Needs:** `acceptance`. **Output:** `contract`: agreed contract revision, workstreams, and ownership. **Check:** before fan-out, the thin blocking integration path works.
3. **Build the workstreams.** Complete authorized work. Independent workstreams run in parallel within their owned files; use [Deliver](../../../deliver/SKILL.md) for coordination and keep the critical path moving. Routine work is one workstream done directly. **Needs:** `contract`. **Output:** `workstream`: each workstream's work and boundary-check result, separate from integration. **Check:** each workstream passes its boundary checks. **On fail:** → step 2 if a workstream cannot meet the contract; stop affected dependents, since the revised contract makes every workstream built on it stale.
4. **Integrate.** Join returned work against the contract and preserve concurrent changes. **Needs:** `contract`, `workstream`. **Output:** `change`: current integrated artifact state, separate from worker returns. **Check:** every workstream is joined and the integrated paths pass their checks. **On fail:** → step 3 for the workstream that breaks integration. → step 2 if the contract itself is wrong.
5. **Verify the changed behavior.** Use [Verify](../../../verify/SKILL.md) for checks and actual entry-point exercise, including maintaining and linting an existing verification map for new or moved paths. **Needs:** `acceptance`, `change`. **Output:** `evidence`: revision-specific evidence for each acceptance condition and explicit gaps. **Check:** current proof covers both behavior and integration; passing app tests alone does not validate a map. **On fail:** → step 3 for the workstream that owns a failed condition. → step 4 if every workstream passes but the joined behavior fails. → step 2 if the contract is wrong. → step 1 if the condition itself is wrong, which needs the user.
6. **Review and hand off.** Use [Review](../../../review/SKILL.md), scaled to the change. **Needs:** `change`, `evidence`. **Output:** `findings`: each accepted or rejected with a reason. **On fail:** → step 3 for an accepted finding in one workstream. → step 4 for one in how the work is joined. → step 2 if it shows the contract is wrong. Then recheck only the evidence it makes stale. **Completion check:** accepted work is integrated, verified, and reviewed where required. Missing required proof leaves an explicit gap and next action. Local completion stops here unless PR delivery is authorized.
