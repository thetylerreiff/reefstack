# Shipping reviewed changes

Use only when the user explicitly authorizes landing a reviewed pull request or an ordered stack. Authorization to finish local work, open a pull request, or observe green CI does not authorize merging. Shipping permission never includes deployment or release unless the user also authorizes those actions. Do not ask again for merge permission already granted in the current task.

1. **Resolve the authorized change set.** Identify the exact pull request or ordered stack, target branch, dependencies, and scope covered by the user's merge authorization. **Output:** authorized pull requests in dependency order. **Check:** no unrelated pull request or downstream release action is added.
2. **Read current proof.** For each candidate, inspect its current head and base, review state, mergeability, checks, and relevant tests. **Output:** evidence tied to each current head. **Check:** green CI alone is insufficient; required review and scope checks must also pass.
3. **Refresh stale evidence.** If a head changes, identify and rerun the affected checks and review the changed diff before landing it. For a stack, confirm dependencies and shared changes still apply in order. **Output:** refreshed proof or a precise blocker. **Check:** do not rely on results from superseded heads.
4. **Land only the proved prefix.** Immediately before each merge, recheck head/base identity and use the host's expected-head guard when available. Changed identities return to evidence review. Merge only the authorized, verified contiguous prefix through the protected merge path; verify the actual landed result before advancing. **Output:** landed pull requests and their resulting revisions. **Check:** refresh affected downstream proof after a base changes; stop at the first unverified, blocked, or unauthorized item. Do not force-push, bypass protections, or equate a queued merge with a completed merge.
5. **Report completion and limits.** State exactly what landed and what remains, with blockers and current evidence. **Output:** accurate partial or complete handoff. **Check:** do not imply deployment or release; if maintaining a canonical task record, reconcile it and use the shared final handoff helper in [Task record](../task-record.md).
