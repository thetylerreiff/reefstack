# Feature playbook

Use for authorized new or changed observable behavior. Structure-only changes belong to [Refactoring](refactoring.md), measured optimization to [Performance](performance.md), and disposable decision experiments to [Prototype](prototype.md). A routine change uses only relevant steps and targeted checks; an obvious small edit stays direct. Use [Design](../../skills/design/SKILL.md) when ownership or shared contracts need settling.

1. **Define the result and open the record.** Capture the user's outcome, constraints, authorization, and affected user paths. For substantial work, create or reuse the [task record](../task-record.md) now, with these acceptance conditions and the remaining work items. **Output:** the record path and initial contents, or the reason routine work needs no record. **Check before substantial implementation:** the record exists on disk; reading its template or keeping a conversation plan does not complete this step. Settle any blocking product choice before dependent work; routine work skips inapplicable design ceremony.
2. **Set contracts and ownership.** Describe caller behavior, shared shapes, dependencies, writable boundaries, and representative cases. **Output:** agreed contract revision and work ownership. **Check:** prove the thin blocking integration path before fan-out. Name independent workstreams, shared state, and the smallest safe decomposition; tightly coupled work stays with the parent.
3. **Implement and integrate.** Complete authorized work, preserve concurrent changes, and integrate returned work against the contract. Use [Deliver](../../skills/deliver/SKILL.md) for coordination. Launch independent helpers together and keep the critical path moving; stop affected dependents if a shared contract fails. **Output:** current integrated artifact state, separate from worker returns. **Check:** each meaningful unit passes its boundary checks before dependent work proceeds.
4. **Verify the changed behavior.** Use [Verify](../../skills/verify/SKILL.md) for checks and actual entry-point exercise, including maintaining and linting an existing verification map for new or moved paths. **Output:** revision-specific evidence for each acceptance condition and explicit gaps. **Check:** current proof covers both behavior and integration; passing app tests alone does not validate a map.
5. **Review and hand off.** Use [Review](../../skills/review/SKILL.md) for substantial or consequential changes, then recheck affected paths after fixes. **Completion check:** accepted work is integrated, verified, and reviewed where required. For recorded work, reconcile the record, inspect its final saved-text readback, and copy the exact Record line using [the shared handoff](../task-record.md#close-the-record-then-hand-it-off). Missing required proof leaves an explicit gap and next action. Local completion stops here unless PR delivery is authorized.
