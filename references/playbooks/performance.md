# Performance playbook

Use for an authorized improvement to measured latency, throughput, resource usage, or another performance target. A request to explain slowness without changes stays in [Investigation](investigation.md). Agree a target or bounded stopping condition before implementation. Stop when it is met, the scoped hypothesis fails, or evidence is unavailable; a new optimization hypothesis needs a deliberate scope decision. This is not an open-ended hillclimbing loop.

1. **Define and measure the baseline.** Name the user-visible workload, metric, units, target, environment, and source revision. Use representative data and repeat measurements enough to expose noise; account for warmup, caches, and relevant load. **Output:** reproducible commands and baseline artifacts. **Check:** the measurement covers the actual slow path, not an easier proxy. If access or workload validity prevents measurement, report the limitation rather than inventing a number.
2. **Locate the limiting work.** Use traces, profiles, or focused experiments to distinguish plausible causes. Follow [Diagnose](../../skills/diagnose/SKILL.md) where useful. **Output:** a supported bottleneck and falsifiable improvement hypothesis. **Check:** observations explain the cost; do not infer a performance ceiling from source inspection alone.
3. **Bound and implement the change.** Preserve correctness and explicit resource tradeoffs. For substantial implementation, open or reuse the [task record](../task-record.md) before edits, recording the baseline and target. **Output:** the smallest justified change and relevant correctness checks. **Check:** one meaningful hypothesis can be evaluated without unrelated optimizations obscuring attribution.
4. **Compare under matched conditions.** Rerun the same workload with comparable hardware, configuration, data, and measurement method; alternate or repeat baseline/candidate runs when drift matters. **Output:** before/after values, variation, commands, artifacts, and the tested revision. **Check:** correctness still holds and the improvement exceeds noise without unacceptable regressions. Label inconclusive results; keep, revise, or revert only the task's own change based on evidence and the authorized target.
5. **Review and stop at the target.** Obtain fresh review when substantial or consequential; recheck affected measurements after fixes. **Output:** measured impact, resource tradeoffs, and remaining limits. **Completion check:** no unsupported speedup claim or indefinite optimization loop. Reconcile any record and use [the final readback/link procedure](../task-record.md#close-the-record-then-hand-it-off).
