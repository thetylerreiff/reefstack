# Prototype playbook

Use when the user authorizes a disposable experiment to choose a design, interaction, or technical approach. Its deliverable is a supported decision and an explicitly experimental artifact. A read-only question stays in [Investigation](investigation.md); production implementation belongs to [Feature](feature.md).

1. **Name the decision.** Identify the uncertainty, constraints, and the observation that could resolve it. **Output:** a narrow question and success criteria. **Check:** the experiment answers a consequential unknown; facts that can be observed are not turned into unnecessary preference questions.
2. **Bound the experiment.** Choose a small set of meaningful alternatives when comparison helps, and an isolated scratch location without changing production source or shared data. **Output:** experiment scope, alternatives, scratch location, and a bounded stopping condition (enough evidence for the decision, a stated time limit, or a named blocker). **Check:** the user's authorization covers the proposed writes and access. A bounded sketch needs no full delivery ceremony or permanent record; use a [task record](../task-record.md) for substantial or consequential implementation, or when dependencies or handoff make one necessary.
3. **Build just enough to observe.** Use the lightest implementation that exercises the question. Keep shortcuts and mocked dependencies explicit. **Output:** a runnable experiment, labeled as disposable. **Check:** the mechanism being decided is real enough to test; a mock cannot establish unimplemented behavior or real-world performance.
4. **Try the alternatives on the relevant surface.** Drive interactions, run commands, or capture observations against the same criteria. **Output:** screenshots, measured behavior, or other decision evidence. **Check:** the observation supports the choice; name inaccessible paths and uncertainty instead of treating a sketch as production validation.
5. **Recommend and hand off.** Explain the choice, tradeoffs, unresolved questions, and artifact location. **Output:** a decision with the experimental limitations. **Completion check:** transition to Feature only when production work is authorized; a prototype request alone does not authorize promotion, installation, deployment, or publishing. Clean up only task-owned resources when appropriate, preserving useful artifacts. If maintaining a record, reconcile it and use [the final readback/link procedure](../task-record.md#close-the-record-then-hand-it-off).
