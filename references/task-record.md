# Task record

Use one canonical record for authorized substantial implementation. Routine work needs one only for real dependencies or handoff; small, obvious tasks need none. Read-only investigation, review, and resume do not create or edit a record unless the user explicitly authorizes that artifact.

Default location: `.reefstack/tasks/<task-slug>.md`; keep supporting evidence beside it in `.reefstack/tasks/<task-slug>-evidence/`. Reuse an equivalent task document when one already exists. Create the minimal record before the first substantial implementation edit or implementation assignment, after inspecting enough to scope the work; fill evidence as it arrives. The top-level agent handling the user's task owns the record, including after restart or compaction. An assigned worker sends receipts to that coordinator without editing its record, unless explicitly handed ownership. A former agent or worker named in a record is not a live owner to wait for. Task records are excluded from release packages and are not committed unless requested or established repository convention requires it. Do not create an automatic commit or push.

Use [the template](task-record-template.md). Keep it concise and update it when user requirements change, contracts are decided, workers hand off, checks run, work pauses or resumes, and at final handoff. Do not log each action. Update current state in place; preserve consequential decisions and supersede a wrong decision with its correction and reason. Before returning, reconcile Current state, Work items, Verification, and Resume together against the artifact. Checked boxes do not override old pending-work text. Keep the actual next action and unresolved blockers visible; never mark complete while material gaps remain.

Record work items with owner, dependency or contract revision, status, and acceptance condition. Distinguish **returned** worker work from **integrated** work and from **verified** work. Receipts identify the revision or content snapshot (including dirty state), method or command, observed result, evidence location, and gaps. After changed requirements, contracts, or code, mark affected evidence and downstream work stale; recheck only impacted paths. Preserve completed work backed by still-valid evidence.

[Resume](playbooks/resume.md) owns continuation: task selection, reconciliation against current instructions and files, stale evidence, and the next dependent action. Do not infer a pause from context compaction or “keep going”; pause only on explicit request.

At a pause or handoff, record the working directory, branch/base revision when available, dirty files, any live workers or processes, outstanding findings, and the first action to take next. Mention the record path in the handoff so the next agent can locate it. Preserve local work without committing, resetting, or stopping unrelated processes. An equivalent non-Git content snapshot is sufficient outside a repository.

## Close the record, then hand it off

For a task with a record, make its final update before writing the final response. Run `python3 <package>/scripts/task_handoff.py <record-path>` after that update. This read-only helper returns the complete saved text, its content hash, and an absolute Markdown link. Inspect the returned text for agreement between Current state, Work items, Verification, and Resume. If it needs a correction, edit it and run the helper again; an earlier readback does not cover later edits.

Copy the helper’s final standalone `Record:` line verbatim into the final response. It contains the same `markdown_link` as the structured receipt; do not reconstruct the path. This is the final completion step, including at a requested pause. Do not substitute a source-code link or a promise to update the record. The helper verifies the bytes read, not the truth of the record's claims. Small tasks without a record skip this step entirely.

When the native `Stop` hook is trusted, it checks the current turn’s helper receipt against the saved record and final link. A miss requests one correction; a second miss is surfaced as an unverified handoff rather than looping. The guard never edits files. If the user explicitly requires a response without a link or another incompatible output format, run the helper with `--no-guard`; user instructions take precedence, and the readback remains available. Missing native transcripts (including ephemeral sessions), unsupported transcript formats, and records outside the default task directory are not covered. The helper and final-response step still apply on those hosts.
