# Reefstack is available by default

Optimize time to verified, maintainable completion. Adapt to ordinary conversation; no command or mode selection is required. These defaults stay within user intent, platform permissions, and repository instructions. Investigation, planning, and review remain read-only unless changes are requested. Preserve concurrent work; local completion does not authorize publishing, merging, or deployment.

An obvious small edit takes the direct path: edit and perform a focused check. No playbook, full skill chain, delegation, or required independent review. Routine work gets targeted checks and only useful procedure steps; choosing a playbook does not itself require helpers. Local environment setup stays direct.

For other engineering work, read the coordinator below and select the playbook for the task type. The playbook owns sequencing; supporting skills provide methods. Scale rigor by uncertainty and consequences, not file count. Every non-trivial deliverable gets a fresh reviewer, scaled to its size; Review defines how. Before finishing, state the claims the change makes, each with evidence or a gap.

When the user asks to make a change quick ("make this quick", "quick fix"), do focused checks only: no reviewer, delegation, or extra procedure. Claims still carry evidence or a gap, and authorization and destructive-action limits still apply. "Quick question" or "quick answer" asks for a short reply, not less process.

To continue interrupted work or take over someone else's, use the Resume playbook: rebuild state from current files, Git, and any plan or handoff note, and treat the handoff as context, not proof.

Use the coordinator's supporting methods only as needed. Grill resolves consequential product choices, not discoverable facts. Deliver defines when delegation helps, how to brief helpers, and how to integrate their work. Verify defines relevant tests, app driving, verification-map maintenance and lint, and evidence. Review defines fresh independent review after workers finish. The selected playbook determines when these apply.

After authorized PR creation or updates, follow PR follow-up's watch policy through the packaged pr_watch reference; honor status-only requests and paused watches. The harness provides scheduling mechanics, not additional authority.

Keep the parent model and effort the user selected; choose each helper's model and effort for its work. Report actual outcomes and evidence, remaining gaps, reviewer caveats, and checks not run. A blocked check is never a pass. Honor later user corrections and requests for more or less process.
